# 涵洞三维交互教学网页开发规划

> 用途：工程制图课程“涵洞图”教学辅助网页  
> 交付对象：Codex / 前端开发人员  
> 目标：通过可旋转三维模型、爆炸分解/组合、构件聚焦、剖切透明、尺寸标注与三面投影联动，帮助学生建立“二维工程图 ↔ 三维结构 ↔ 构件关系”的空间认知。

---

## 1. 项目定位

本网页不是单纯的“3D 模型展示器”，而应做成一个面向工程制图教学的**结构认知 + 空间想象 + 图物对应**交互课件。

核心教学链路：

1. **先看整体**：理解涵洞由哪些主要构件组成，以及构件之间的位置关系。
2. **再做分解**：通过爆炸动画拆解构件，理解各构件的独立形体。
3. **逐件观察**：聚焦底板、翼墙、面墙、洞身，观察其形成方式与关键形体特征。
4. **剖开看内部**：理解底板底面的燕尾形空槽、面墙穿孔、洞身拱形通道等不易从外表直接看出的结构。
5. **回到工程图**：通过正面投影图、水平投影图、侧面投影图与三维模型同步联动，训练图物转换能力。
6. **最后重组**：按结构认知顺序重新组合涵洞，形成完整空间概念。

网页应兼顾“酷炫感”和“教学清晰度”。视觉表现可以有科技感，但不能为了动画效果牺牲构件边界、尺寸关系和工程图阅读。

---

## 2. 课件中涵洞结构的理解与建模依据

根据《涵洞图课件》1—12 页，网页中的模型至少应包含以下四类主体构件：

### 2.1 底板 Bottom Slab

- 位于整个结构最下部。
- 课件描述为可由长方体切割形成，长度贯穿全洞。
- 是洞身、面墙和翼墙的承托基础。
- **重要隐蔽形体**：底板底面中间部分存在**燕尾形空槽**，必须在“透明/翻转/剖切”模式中明确展示。
- 建模时不要只做成普通矩形板，应保留两端外扩/台阶以及底部空槽等课件中可辨识特征。

### 2.2 翼墙 Wing Wall

- 位于洞口两侧，为挡土墙。
- 平面上呈**八字形展开**。
- 单片翼墙不是简单竖直矩形板，而是具有斜边、变高和一定厚度的空间实体。
- 左右翼墙关于涵洞中轴线对称布置；涵洞两端均存在对应洞口构造时，应按照课件完整模型表现。
- 翼墙是学生理解“平面斜置构件在三面投影中如何表达”的重点对象。

### 2.3 面墙 Headwall / End Wall

- 位于翼墙之后的直立部分。
- 可理解为由实体切割，并开出与洞身相匹配的拱形孔洞。
- 面墙顶部两端有**倒角**，课件专门强调，应作为重点可视化细节。
- 面墙与洞身端部相交，需让学生看清二者不是同一个构件。

### 2.4 洞身 Culvert Barrel

- 位于底板之上，整体呈狭长形。
- 由**边墙 + 拱圈**组成。
- 中间形成拱形穿孔，供水流通过。
- 课件尺寸图中可辨识出内外拱圆弧关系，建模应采用真正的圆弧/拱形截面，而不是用近似矩形替代。
- 洞身应支持“半透明”和“横向剖切”，让学生明确内轮廓、外轮廓以及拱圈厚度关系。

### 2.5 课件中必须保留的重点细节

开发时将以下内容标记为 `must-have geometry details`：

- 底板底面中间的燕尾形空槽。
- 翼墙八字形布置。
- 面墙拱形穿孔。
- 面墙顶部两端倒角。
- 洞身由边墙与拱圈组成。
- 洞身中间为贯通的拱形孔洞。
- 涵洞纵向长度与洞口构造的连接关系。
- 课件尺寸图中明确给出的圆弧半径、长度、厚度、相对标高等参数，应统一进入参数表，不得散落硬编码。

> **尺寸录入原则**：所有数字以原课件尺寸图为唯一依据。对截图中不够清晰或存在歧义的尺寸，不得由开发人员自行猜测；先在参数表中标记 `TODO_VERIFY`，待教师确认后再锁定。

## 3. 教学网页的总体信息架构

建议采用“单页沉浸式应用”结构，三维场景始终占据视觉中心，教学功能以浮层/侧栏方式出现。

### 3.1 页面主布局

桌面端：

```text
┌─────────────────────────────────────────────────────────────┐
│ 顶部导航：整体认知 | 爆炸分解 | 构件学习 | 三面投影 | 课堂挑战 │
├──────────────┬──────────────────────────────┬───────────────┤
│              │                              │               │
│ 左侧教学导航 │          3D 主视窗            │ 右侧信息卡片    │
│ /构件树      │                              │ /尺寸/说明      │
│              │                              │               │
├──────────────┴──────────────────────────────┴───────────────┤
│ 底部控制条：爆炸滑杆 | 自动演示 | 剖切 | 透明 | 标注 | 复位      │
└─────────────────────────────────────────────────────────────┘
```

移动端：

- 3D 视窗全屏优先。
- 构件树、说明卡片改为底部抽屉。
- 爆炸滑杆保持常驻。
- 相机预设按钮收纳为浮动菜单。

## 4. 核心交互模块

## 4.1 模块 A：整体认知

默认进入完整涵洞三维模型。

### 功能

- 鼠标左键旋转、滚轮缩放、右键/中键平移。
- 手机支持单指旋转、双指缩放/平移。
- 鼠标悬停构件：描边高亮 + 显示名称。
- 单击构件：选中并弹出教学卡片。
- 双击构件：相机平滑飞近该构件。
- 空白处双击：恢复整体视图。

### 默认构件配色

沿用原课件的识别逻辑，增强学生从课件到网页的迁移：

| 构件 | 建议主色 | 说明 |
|---|---|---|
| 底板 | 红色系 | 与原课件整体模型一致 |
| 翼墙 | 黄色系 | 强调八字形展开 |
| 面墙 | 绿色系 | 与洞身形成明显边界 |
| 洞身 | 青蓝色系 | 突出拱圈与纵向通道 |

选中时不直接改变主色，而用发光轮廓、边缘描线和轻微呼吸光提示，避免破坏构件颜色记忆。

---

## 4.2 模块 B：爆炸分解 / 组合

这是网页的主视觉和主交互。

### 操作方式

- 底部提供 `0—100%` 爆炸滑杆。
- 支持鼠标拖拽、键盘方向键、触屏拖动。
- 提供按钮：
  - `一键分解`
  - `一键组合`
  - `逐步分解`
  - `自动演示`
  - `暂停`

### 推荐爆炸逻辑

爆炸动画不是随机向外散开，而应服务于构件关系教学：

1. **底板作为空间基准，保持原位**。
2. **洞身沿 Z 轴上移**，暴露其与底板的接触关系。
3. **前后面墙沿涵洞纵轴向两端移出**。
4. **左右翼墙沿各自八字展开方向斜向外移**。
5. 对称构件保持同步、镜像运动。

建议每个构件的爆炸位移由配置表统一管理：

```ts
interface ExplodeConfig {
  componentId: string;
  direction: [number, number, number];
  distance: number;
  delay?: number;
}
```

### 动画要求

- 使用缓入缓出，不要机械匀速。
- 爆炸 100% 时仍保持构件与整体关系可理解，不能飞得过远。
- 动画过程中标签跟随构件。
- 相机可轻微后退以保证所有构件始终处于视野内。
- 组合时严格反向回到 `homeTransform`，不得产生浮点累积偏移。

### 教学增强

当滑杆经过特定节点时自动出现简短提示：

- 0%：完整涵洞
- 25%：底板与上部结构关系
- 50%：洞身与面墙关系
- 75%：翼墙八字形布置
- 100%：四类构件完全分解

## 4.3 模块 C：逐构件学习

左侧构件树：

```text
涵洞
├── 底板
├── 洞身
│   ├── 边墙
│   └── 拱圈
├── 前端面墙
├── 后端面墙
├── 前端左翼墙
├── 前端右翼墙
├── 后端左翼墙
└── 后端右翼墙
```

> 如果最终课件模型只要求重点讲解一端洞口，可在配置中关闭另一端翼墙/面墙教学节点，但三维整体模型仍建议保持完整。

### 选择某构件后的行为

1. 其他构件降低到 10%—20% 透明度。
2. 当前构件保持实体并加轮廓线。
3. 相机飞到最能表达该构件形体的轴测角度。
4. 右侧卡片显示：
   - 名称
   - 结构作用
   - 形体生成方式
   - 关键尺寸
   - 工程制图观察提示
5. 出现“查看三面投影”按钮。

### 教学卡片示例：翼墙

```text
翼墙
位置：洞口两侧
作用：挡土
形体特点：平面呈八字形展开；立面高度变化；具有一定厚度
观察重点：比较其水平投影与正面投影中斜边的变化
```

## 4.4 模块 D：结构透视与剖切

该模块用于理解外表不可见的空间形体。

### 透明模式

提供三档：

- 实体
- 半透明
- X-Ray 线框

可单独控制构件透明度。

### 剖切模式

至少支持 3 个剖切方向：

1. **横向剖切**：看洞身拱形截面、边墙和拱圈。
2. **纵向剖切**：看洞身贯通关系与底板。
3. **水平剖切**：看翼墙八字形展开和面墙位置。

建议使用 Three.js clipping planes，而不是制作多套模型。

### 底板翻转 / 底视模式

底板是重点：增加一个独立的“看底面”按钮。

点击后：

- 暂时隐藏其他构件。
- 底板缓慢绕纵轴翻转 180°。
- 高亮燕尾形空槽。
- 用箭头标签说明“底板底面中间部分为燕尾形空槽”。

---

## 4.5 模块 E：三维模型与三面投影联动

这是工程制图课程区别于普通 3D 展示网页的关键功能。

### 视图名称必须采用规范术语

- 正面投影图
- 水平投影图
- 侧面投影图
- 三面投影图

不要使用“正视图 / 俯视图 / 左视图 / 三视图”作为主界面正式术语。

### 两种显示模式

#### 模式 1：三窗联动

```text
┌──────────────────┬──────────────────┐
│ 正面投影图        │ 侧面投影图        │
│ Orthographic      │ Orthographic      │
├──────────────────┼──────────────────┤
│ 水平投影图        │ 三维轴测图         │
│ Orthographic      │ Perspective       │
└──────────────────┴──────────────────┘
```

- 四个视窗共用同一套模型状态。
- 3D 中选择一个构件，三个投影窗口中同步高亮。
- 爆炸状态下默认禁止投影联动，或提供“爆炸投影”教学开关，避免初学者混淆。

#### 模式 2：投影生成动画

点击“生成投影”：

1. 显示三个投影面。
2. 从模型关键轮廓向投影面发出细线。
3. 投影面逐步形成轮廓。
4. 投影面展开到同一屏幕平面。

该动画可以做成 6—10 秒自动演示，用于课堂讲授“空间形体如何形成工程投影”。

---

## 4.6 模块 F：尺寸与标高展示

尺寸信息不要永久全部显示，否则会严重遮挡模型。

### 尺寸层级

- `关键尺寸`：只显示最重要的总体长、宽、高、拱半径等。
- `构件尺寸`：选中构件时显示其相关尺寸。
- `全部尺寸`：用于教师讲解或核对。

### 技术实现

尺寸线建议由 3D 线段 + CSS2D 标签组成：

- extension line
- dimension line
- arrow heads
- numeric label

尺寸单位统一使用 `mm`，UI 中可提供“显示/隐藏单位”。

### 相对标高

课件中出现的相对标高信息，应设计独立开关：

- 基准面 `±0.000`
- 标高符号
- 标高引线

若课件某个标高数值不够清晰，参数表中标记为待核对，不允许程序自行推断。

---

## 4.7 模块 G：工程制图课堂挑战

完成核心模型后再开发，不作为 MVP 阻塞项。

### 挑战 1：认构件

系统随机高亮一个构件，学生选择名称。

### 挑战 2：图找物

显示某个构件的正面/水平/侧面投影轮廓，让学生在 3D 模型中点击对应构件。

### 挑战 3：物找图

高亮某个构件，在多个二维投影选项中选择正确表达。

### 挑战 4：拼装涵洞

将 3D 构件打散，让学生按照空间位置拖拽回正确位置。

判定不需要做到像 CAD 一样精确，可采用“进入目标包围盒 + 朝向误差在阈值内”自动吸附。

## 5. 视觉设计方案

## 5.1 总体风格

关键词：

- 深色科技背景
- 工程蓝图网格
- 青蓝环境光
- 局部暖色强调
- 半透明玻璃信息面板
- 发光轮廓
- 细线工程标注
- 克制的粒子/光效

避免：

- 过度霓虹导致尺寸看不清。
- 材质过于真实导致结构边界不明确。
- 大面积动态背景影响课堂投影。

## 5.2 模型材质

优先采用“教学模型材质”，而不是写实混凝土材质：

- 轻微粗糙度。
- 不使用高反射金属效果。
- 构件交界处使用 AO / Contact Shadow 增强层次。
- 默认开启边缘线/轮廓线。
- 可提供“实体教学色 / 混凝土写实色”切换，写实模式为增强项。

## 5.3 场景

建议：

- 深灰蓝渐变背景。
- 地面为低对比度网格，不做真实地形。
- 模型下方使用柔和 contact shadow。
- 环境中可有非常轻微的浮动粒子，但课堂模式下可关闭。

## 6. 三维模型的参数化设计

不要把所有几何尺寸直接写死在 React 组件中。

建议创建：

```text
src/config/culvertDimensions.ts
```

示意结构：

```ts
export interface CulvertDimensions {
  bottomSlab: {
    length: number;
    width: number;
    thickness: number;
    dovetailGroove: {
      enabled: boolean;
      topWidth: number;
      bottomWidth: number;
      depth: number;
      length: number;
    };
  };

  barrel: {
    length: number;
    innerRadius: number;
    outerRadius: number;
    sideWallHeight: number;
  };

  headwall: {
    thickness: number;
    topWidth: number;
    totalHeight: number;
    chamferX: number;
    chamferZ: number;
  };

  wingWall: {
    thickness: number;
    rootHeight: number;
    endHeight: number;
    planAngle: number;
    length: number;
  };
}
```

### 参数来源注释

每个重要参数旁边写清楚来源页码，例如：

```ts
innerRadius: 2500, // 课件 p12，需教师最终复核
outerRadius: 3500, // 课件 p12
```

无法可靠辨认的数据：

```ts
someDimension: TODO_VERIFY,
```

不要“看起来差不多”就填入数值。

## 7. 建模技术路线

## 7.1 推荐方案：代码参数化建模

考虑到本项目结构规则、需要尺寸教学、需要剖切和动态分解，推荐直接用 Three.js 几何体参数化生成，而不是先做 Blender 再导出静态 glTF。

### 各构件建议

#### 底板

- 主体：`BoxGeometry` + 自定义平面轮廓拉伸。
- 燕尾形空槽：使用 CSG 布尔减法。
- 若底板平面有台阶/局部外扩，使用 `Shape + ExtrudeGeometry`。

#### 洞身

- 在二维截面中定义：
  - 内拱圆弧
  - 外拱圆弧
  - 左右边墙
- 形成闭合截面后沿纵向拉伸。
- 可使用 `Shape.holes` 直接形成贯通孔洞，比“实体再减洞”更稳定。

#### 面墙

- 先生成梯形/变截面墙体轮廓。
- 用与洞身内孔一致的拱形轮廓做穿孔。
- 顶部两端倒角必须真实建模，不可只用贴图表现。

#### 翼墙

- 使用自定义四边形/多边形截面 + 拉伸。
- 通过 `rotationY` 或顶点坐标直接形成八字布置。
- 左右翼墙通过镜像参数生成，避免重复代码。

### 几何精度

- 圆弧分段不低于 48，桌面端推荐 64。
- 在移动端根据性能可降到 32—48。
- 边缘显示使用独立 `EdgesGeometry` 或后处理 OutlinePass。

## 8. 推荐技术栈

### 前端框架

- Vite
- React
- TypeScript

### 3D

- `three`
- `@react-three/fiber`
- `@react-three/drei`

### CSG / 几何布尔

优先二选一：

- `three-bvh-csg`
- 或稳定的 Three.js CSG 实现

尽量减少运行时频繁 CSG。参数确定后生成一次并缓存 geometry。

### 状态管理

- Zustand

管理：

- 当前教学模式
- 选中构件
- 爆炸比例
- 透明度
- 剖切面
- 尺寸显示级别
- 相机预设

### 动画

优先：

- React Three Fiber `useFrame` + easing
- 或 GSAP

不要同时混用多套复杂动画状态系统。

### UI

- Tailwind CSS
- Lucide React icons
- 可选：Framer Motion 只负责 2D UI 动画

### 部署

纯静态构建：

- GitHub Pages
- Vercel
- Netlify

均可，不依赖后端。

## 10. 组件数据模型

建议每个构件都使用统一数据结构：

```ts
export interface CulvertComponentMeta {
  id: string;
  nameZh: string;
  nameEn: string;
  category: 'bottom-slab' | 'barrel' | 'headwall' | 'wing-wall';

  homePosition: [number, number, number];
  homeRotation: [number, number, number];

  explodeDirection: [number, number, number];
  explodeDistance: number;

  color: string;
  teachingSummary: string;
  drawingTips: string[];
  keyDimensions: string[];
}
```

每个 3D 物体都设置：

```ts
mesh.userData.componentId = 'front-left-wing-wall';
```

这样拾取、标签、投影联动、爆炸动画、测验可以共享同一套 ID。

## 11. 相机系统

必须提供以下预设：

- 默认轴测视角
- 正面投影方向
- 水平投影方向
- 侧面投影方向
- 洞口近景
- 洞身纵向视角
- 底板底视角

点击预设时采用 0.8—1.5 秒平滑过渡。

### 投影相机

- 3D 主视窗：PerspectiveCamera
- 三面投影视图：OrthographicCamera

三面投影不能用透视相机模拟。

## 12. 教学引导模式 Guided Tour

首页提供按钮：`开始 5 分钟结构导览`

建议脚本：

### Step 1 — 整体

“涵洞主要由底板、翼墙、面墙和洞身组成。”

相机环绕 20°—30°。

### Step 2 — 底板

其他构件透明，底板高亮。

随后翻转底板，展示燕尾形空槽。

### Step 3 — 洞身

洞身上移并单独显示。

横向剖切，显示边墙、拱圈和内部通道。

### Step 4 — 面墙

面墙拉出。

高亮拱形开孔与顶部倒角。

### Step 5 — 翼墙

两侧翼墙向外展开。

切换到水平视角，突出八字形布置。

### Step 6 — 三面投影

模型恢复组合，进入四视窗联动。

### Step 7 — 重新组合

播放组合动画结束导览。

## 13. 教学信息文案原则

每张卡片控制在 3—5 行核心信息，避免把课件全文搬上网页。

建议固定模板：

```text
【名称】底板
【位置】涵洞最下部
【形体】以板状实体为主，经局部切割形成
【关键特征】贯穿全洞；底面中部设燕尾形空槽
【制图观察】注意底面不可见轮廓与水平投影中的外形变化
```

对于尺寸内容，采用“点一下尺寸线再显示说明”，不要长篇文本覆盖模型。

## 14. UI 状态设计

建议全局状态：

```ts
interface CulvertUIState {
  mode:
    | 'overview'
    | 'explode'
    | 'component'
    | 'section'
    | 'projection'
    | 'quiz';

  selectedComponentId: string | null;
  explodeProgress: number;       // 0..1
  transparencyMode: 'solid' | 'transparent' | 'xray';
  dimensionMode: 'off' | 'key' | 'component' | 'all';
  clippingMode: 'off' | 'cross' | 'longitudinal' | 'horizontal';
  labelsVisible: boolean;
  autoRotate: boolean;
}
```

不同模式之间避免互相打架。例如：

- `projection` 模式默认强制 `explodeProgress = 0`。
- `quiz` 模式关闭全部尺寸标签。
- `section` 模式暂停自动旋转。

## 15. 酷炫效果清单（有教学意义的才保留）

### 第一优先级

- 爆炸分解/组合
- 构件悬停发光描边
- 相机飞行
- 半透明 / X-Ray
- 剖切面动画
- 3D 标签跟随
- 三面投影联动

### 第二优先级

- 投影生成动画
- 水流方向动画：用少量粒子/流线从洞身中穿过，说明“通水”功能
- 轻微环境粒子
- 结构组合成功时的边缘扫光

### 不建议

- 大量烟雾、爆炸粒子。
- 过强 Bloom。
- 复杂真实地形、树木、车辆等与教学无关资产。
- 长时间不可跳过的开场动画。

## 16. 性能与兼容性目标

### 性能

- 常规教学电脑：目标 60 FPS。
- 普通手机：不低于 30 FPS。
- 首屏可交互时间尽量 < 3 s（正常校园网络环境）。
- 不使用超大纹理；本项目尽量使用纯几何 + 程序材质。

### 优化

- 所有 geometry `useMemo` 缓存。
- 对称翼墙共用 geometry，使用 transform 镜像。
- 尺寸标签按需挂载。
- 移动端关闭高成本实时阴影或降低 shadow map。
- DPR：`[1, 1.75]` 自适应。

### 浏览器

优先支持：

- Chrome / Edge 最新版
- Safari 最新版
- iPad Safari

检测 WebGL2；若不可用，显示友好提示。

## 18. 几何验收清单

Codex 每完成一个模型阶段，需要截图并按以下清单验收：

### 整体

- [ ] 四类主要构件齐全。
- [ ] 构件不存在明显穿插。
- [ ] 洞身纵向中心线与底板一致。
- [ ] 前后洞口构造位置正确。

### 底板

- [ ] 底板贯穿整个涵洞。
- [ ] 平面轮廓与课件一致。
- [ ] 底部燕尾形空槽真实存在。

### 洞身

- [ ] 内部为贯通拱形孔洞。
- [ ] 内外拱圈同心关系正确。
- [ ] 边墙和拱圈连续连接。
- [ ] 纵向长度正确。

### 面墙

- [ ] 与洞身端部位置对应。
- [ ] 拱形开孔与洞身通道对齐。
- [ ] 顶部两端倒角存在。
- [ ] 墙体厚度方向正确。

### 翼墙

- [ ] 左右翼墙成八字布置。
- [ ] 斜边与高度变化正确。
- [ ] 与面墙、底板衔接位置合理。
- [ ] 对称构件镜像正确。

## 20. 教学验收问题

最终版本不仅要问“好不好看”，还要让学生能回答：

1. 涵洞主要由哪四类构件组成？
2. 底板位于哪里？底部有什么容易被忽略的形体？
3. 为什么翼墙在水平投影中呈八字形？
4. 面墙与洞身有什么区别？
5. 面墙上的拱形孔洞与洞身是什么空间关系？
6. 面墙顶部有什么局部构造细节？
7. 洞身的边墙、拱圈和内部通道是什么关系？
8. 同一构件在正面投影图、水平投影图、侧面投影图中为何形状不同？
9. 从二维投影能否反推出涵洞三维形体？

如果网页能显著降低学生回答这些问题的难度，即达到核心教学目标。

## 21. Codex 开发执行要求

请 Codex 按以下规则执行，不要一次性生成所有功能：

### 开发规则

1. **先几何，后特效。**
2. 每个 Phase 完成后必须能单独运行。
3. 所有尺寸集中到 `culvertDimensions.ts`。
4. 所有爆炸位移集中到 `explodeConfig.ts`。
5. 禁止把尺寸数字散落硬编码到多个组件。
6. 对课件中无法确认的数据使用 `TODO_VERIFY`，不要猜。
7. 所有构件使用稳定唯一的 component ID。
8. 三面投影必须使用 OrthographicCamera。
9. 材质颜色、透明度、选中状态必须由统一状态驱动。
10. 开发过程中至少保留一个“Debug 模式”，可显示：坐标轴、包围盒、构件原点、模型尺寸、剖切面。

### 第一轮 Codex 任务建议

只实现以下内容：

```text
Sprint 1：涵洞核心 3D 几何与基础查看器

1. 初始化 Vite + React + TypeScript + React Three Fiber 项目。
2. 建立 culvertDimensions.ts 参数文件。
3. 参数化创建 BottomSlab、Barrel、Headwall、WingWall。
4. 组合完整 CulvertAssembly。
5. 使用课件配色：红/黄/绿/青。
6. 加入 OrbitControls、网格地面、基础灯光、接触阴影。
7. 加入默认轴测、正面、水平、侧面四个相机预设。
8. 不做爆炸、不做剖切、不做测验。
9. 提供 Debug UI，可显示/隐藏单个构件和坐标轴。
10. README 中列出所有参数及其课件页码来源，所有不确定尺寸标记 TODO_VERIFY。
```

完成 Sprint 1 并经教师确认几何正确后，再进入爆炸动画阶段。

## 22. 最终期望效果

理想成品应让教师在课堂上实现如下演示：

> 打开网页后先展示完整涵洞，鼠标轻轻旋转模型；点击“爆炸”，底板保持原位，洞身上移，前后面墙沿纵向移出，两侧翼墙沿八字方向展开。教师点击“底板”，其他构件变透明，模型自动翻转展示底部燕尾形空槽；点击“洞身”，横向剖切显示边墙、拱圈和内部通道；点击“面墙”，放大顶部倒角；点击“翼墙”，切换水平视角突出八字形布置。最后进入“三面投影”，屏幕同时显示正面投影图、水平投影图、侧面投影图和三维轴测图，点击任一构件四个视窗同步高亮，再播放组合动画恢复完整涵洞。

这应当是一个真正服务于**工程制图空间认知**的交互课件，而不仅是一个三维模型网页。
